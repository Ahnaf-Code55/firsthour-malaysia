FirstHour Malaysia: app map

A snapshot of the code on Oct 26, 2026. It can drift as the code changes.

Overview

FirstHour Malaysia gives a scam victim a sourced plan for the first hour. The person pastes a message or adds a screenshot, and the AI reads only the facts: the amount, the time, the payee, and how the scam started. Each fact must point to the exact words it came from. Plain code then builds the plan from dated official sources in data/, so the AI never writes a step or a phone number.

Reference route, not a completed tour

These three stops follow the same path. Nobody has walked this route as a tour yet, so treat it as a map to read, not a record of completed steps.

1. extractFacts (src/lib/extract.ts)

Search for extractFacts. In fixture mode it returns saved facts. Otherwise it posts the text or screenshot to /api/extract. The result is labelled live, fixture, or offline.

2. validateFacts (server/validate.ts)

Search for validateFacts. A fact survives only if its quote appears word for word in the person's text. Free text that carries a phone number or a link is dropped, so it cannot reach the call script. With a screenshot only, there is no quote to check, so the person checks the value by eye.

3. buildPlan (src/lib/plan.ts)

Search for buildPlan. A pure function with no AI. It keeps steps that match the payment type and time window, sorts them by priority, and fills the call script. Outside bank or e-wallet within one hour, it sets outOfScope.

To change this, start here

  • Add or fix a step: data/steps.json. Each step needs a source URL and a retrievedOn date. scripts/check-sources.mjs fails the build when either is missing or older than 14 days.
  • Change wording: src/i18n/en.json and src/i18n/bn.json. Keep the keys the same in both.
  • Add a bank: data/banks.json.
  • Add a scam warning rule: data/recovery-rules.json.
  • Change the look: src/styles/tokens.css.

A practice to reuse

Decision: the rule "every number comes from a dated official source, and the AI never produces one" is written in devpost/prd.md. A product rule is only as good as its check.

Evidence: tests/validate.test.ts covers free text that carries a phone number or link, tests/injection.test.ts covers hostile input, and scripts/check-sources.mjs enforces the dates. An AI review found that free text could still carry a phone number into the call script, which the tests then guarded.

Reuse: turn each product rule into a test that fails when the rule breaks. Do this on any project where a wrong output could cause harm.

How to run it again

npm install
VITE_FIXTURE=1 npm run dev     # no key needed, uses the saved sample case
npm test                       # runs the unit and end-to-end tests

For live reading, put GEMINI_API_KEY in .env, then run npm run dev without the fixture flag. Keep the key on your machine only.
